# 서재 앱 1단계 설계

- 작성일: 2026-09-27
- 브랜치: `seojae-v1` (GitHub Pages가 `main`을 배포하므로 1단계가 끝날 때까지 `main`에 합치지 않습니다)
- 시안: https://claude.ai/artifact/1xcorzFa57aTKBCUSgMUBV (버전 3, 흑백 모던 · 그린 버튼)

## 1. 목표

지금의 단일 파일 리더(`index.html` 약 3.2MB, 베이츠 한 권)를 여러 권을 담는 **서재 앱(PWA)** 으로 바꿉니다.
1단계에 들어가는 책은 베이츠 『신적 속성의 조화』 한 권이지만, 구조는 뒤에 성경 등 다른 책을 끼울 수 있게 만듭니다.
**기존 기능과 기록(형광펜 139개, 북마크 3개, 진도, 동기화)은 하나도 잃지 않습니다.**

## 2. 범위

**포함**
- 앱 셸, 서재 홈, 하단 탭 바(서재 · 형광펜 · 설정)
- 베이츠 리더 이식: 기존 기능 전부 (5장 참고)
- 새 디자인 시스템과 상세 설정
- 형광펜 4색 → 2색 전환
- 기존 기록 이전과 동기화 호환
- PWA: 매니페스트, 서비스 워커, 오프라인 읽기, 업데이트 알림

**제외 (뒤 단계)**
- 성경 전체. 새한글은 대한성서공회 허락 전에는 싣지 않고, 크롤링도 하지 않습니다. (갓피플 성경앱의 새한글 탑재 협의 결과를 기다립니다.)
- 원문 단어별 인터리니어 (성경 단계에서 함께)
- 베이츠 재번역 (별도 과제, 12장 참고)

## 4. 아키텍처

### 4.1 파일 구성

빌드 도구(번들러) 없이 순수 ES 모듈로 갑니다. 지금처럼 `build.py` 하나로 데이터를 만듭니다.

```
index.html                  앱 셸 (작게)
manifest.webmanifest
sw.js                       서비스 워커 (GitHub Pages는 Service-Worker-Allowed 헤더를 못 주므로 루트에 둠)
app/
  main.js                   진입점, 라우터
  ui.js                     el/txt/svgIcon 등 DOM 도우미, 토스트, 시트
  store.js                  로컬 저장, 상태, 기록 이전(migrate)
  settings.js               설정 모델과 설정 화면, CSS 변수 적용
  sync.js                   동기화 (기존 SYNC 이식), 백업 내보내기/불러오기
  highlight.js              형광펜: 선택 감지, 조각 나누기, 칠하기, 툴바
  library.js                서재 홈
  panels.js                 형광펜 탭, 북마크 목록
  books/treatise.js         '논고형' 책 리더 (베이츠): 장 렌더, 주석 시트, 목차, 진도
  app.css
fonts/                      Pretendard·본문 명조 woff2 (서브셋, 직접 호스팅)
icons/                      앱 아이콘 (180·192·512px, maskable)
books/
  index.json                서재 목록: [{id, type, title, author, year, ...}]
  bates/meta.json           목차, 부(parts), 장 제목, 장별 문단 수
  bates/ch/<id>.json        장별 본문 (en 문단, ko 문단, gist, argument, notes)
```

### 4.2 책 유형 경계

책마다 `type`이 있고, 리더는 유형별 모듈이 맡습니다. 1단계에는 `treatise`(베이츠) 하나뿐입니다.
유형 모듈이 앱에 내놓는 약속은 네 가지입니다.

- `loadChapter(bookId, chId)` → 장 데이터
- `render(chapter, container, ctx)` → 화면 그리기
- `anchorOf(node)` → 형광펜·북마크 위치 `{i, side, offset}`
- `labelOf(chId)` → 목록에 보일 장 이름

형광펜·북마크·동기화는 이 약속만 쓰므로, 나중에 `bible` 유형을 더해도 손대지 않습니다.

### 4.3 주소 (라우팅)

해시 라우팅을 씁니다.

| 주소 | 화면 |
|---|---|
| `#/` | 서재 홈 |
| `#/b/bates` | 베이츠 표지 |
| `#/b/bates/6` | 베이츠 6장 |
| `#/hl` | 형광펜 탭 |
| `#/set` | 설정 탭 |

예전 주소(`#6`, `#p`, `#cover`)는 `#/b/bates/…`로 옮겨 줍니다. 홈 화면에 추가해 둔 예전 바로가기도 계속 열립니다.

### 4.4 빌드

`build.py`는 한 파일에 모두 끼워 넣는 대신 `books/bates/meta.json`과 `books/bates/ch/*.json`을 씁니다.
지금 하는 검증(미아 주석 표지, 문단 수, USFM 코드)은 그대로 둡니다.
빌드 시각을 `app/version.json`과 서비스 워커 캐시 이름에 새겨, 새 버전이 나오면 캐시가 바뀌게 합니다.

## 5. 이식할 기존 기능 (빠짐없이)

- 형광펜: 여러 문단에 걸쳐 칠하기, 칠한 곳 다시 눌러 색 바꾸기·지우기, **주해 팝업 안 형광펜**
- 형광펜 목록: 장 안에서 본문과 주해를 **본문 위치 순**으로 섞어 보여 주기 (2026-09-12 커밋 `b32e0af`의 동작)
- 북마크 (리본), 북마크 목록
- 읽은 표시, 진도(전체 %), 읽던 자리 기억
- 주석 시트: 성경(`s`) · 주해(`t`) · 원어(`o`) · 배경(`b`). 성경 주석 머리의 장·절 배지와 `— 골로새서 1:27` 줄 (`370d7ab`)
- 성경 주석 링크: 새한글성경 공식 리더(`bskorea.or.kr/KNT/?chapter=…&verse=…`), 개역·쉬운성경, ESV, KJV
- 보기 전환: 한글 · 영문 · 대역
- 목차 (아이패드처럼 넓은 화면에서는 옆에 고정)
- 백업 파일 내보내기/불러오기
- 동기화 코드 기반 자동 동기화 (Cloudflare Worker `bates-sync`, KV 하루 쓰기 한도 대책 포함)
- 빌드 시각 표시 (설정 화면)

## 6. 화면

시안을 기준으로 합니다.

- **서재 홈:** 큰 제목 "서재" → 이어 읽기 카드(책, 장, 진도 막대, 그린 버튼) → 책장(글자 표지) → 최근 형광펜 3개.
- **리더:** 위쪽 막대(뒤로 · 장 제목 · 목차), 얇은 진도 선, 본문. 형광펜 툴바는 2색과 지우기.
- **형광펜 탭:** 모든 책의 형광펜. 책과 색으로 걸러 봅니다. 베이츠는 5장의 위치 순 정렬을 따릅니다.
- **설정 탭:** 미리보기 문단이 맨 위에 있고, 바꾸면 바로 반영됩니다. 항목은 7장.
- **아이패드:** 넓은 화면에서는 목차가 왼쪽에 고정되고 본문 폭은 설정값을 따릅니다.

## 8. 데이터 모델과 기록 이전

### 8.1 새 저장 키 (localStorage)

| 키 | 내용 |
|---|---|
| `lib.v` | 이전 완료 표시 (`1`) |
| `lib.hl` | `{ "<책>:<장키>": [ {id, i, side, a, b, c, t, ts, c0?} ] }` |
| `lib.bm` | `[ {book, ch, i, t} ]` |
| `lib.read` | `{ "<책>:<장>": 1 }` |
| `lib.pos` | `{ "<책>": {ch, i} }` 책마다 읽던 자리 |
| `lib.at` | 마지막으로 연 책 |
| `lib.del` | 지운 기록 `{h:{<id>:ts}, b:{<책>:<장>\|<i>:ts}}` |
| `lib.set` | 설정 (기기별) |
| `lib.sync`, `lib.syncat` | 동기화 설정과 마지막 동기화 시각 |

장키와 id 규칙은 지금과 같고, 앞에 책 이름만 붙습니다.
- 본문 형광펜: 키 `bates:6`, id `bates:6|ko|45|358|533`
- 주해 형광펜: 키 `bates:n:6:s20`

### 8.2 이전 규칙 (한 번만 실행)

1. `hb.*` 값을 읽어 위 형태로 바꿔 `lib.*`에 씁니다. **`hb.*`는 지우지 않습니다** (되돌리기용).
2. 형광펜 색: 초록 `g` → 1(그린), 분홍 `p` → 2(레드). 실제 기록에는 이 두 색만 있습니다(초록 99, 분홍 40). 혹시 모를 노랑 `y` · 파랑 `b`는 1(그린)로 옮깁니다. 원래 색은 `c0`에 남깁니다.
3. 지운 기록(`hb.del`)의 id에도 같은 접두사를 붙입니다.
4. 설정은 `hb.fs` · `hb.fsv` · `hb.theme` · `hb.kofont` · `hb.view` · `hb.nav`에서 옮깁니다.
5. 끝나면 `lib.v = 1`.

**판별 규칙:** 키나 id가 알려진 책 이름(`bates:`)으로 시작하지 않으면 예전 형식으로 보고 `bates:`를 붙입니다. `n:6:s20`처럼 콜론이 들어간 예전 키도 이 규칙으로 걸러집니다.

### 8.3 동기화 호환

- 동기화 문서는 **하나 그대로**이고, 형태만 `{app:'lib', v:3, hl, bm, read, del}`로 바뀝니다.
- 새 앱은 내려받은 문서가 v2이든 v3이든, 합치기 전에 8.2의 판별 규칙으로 정규화합니다.
- **아직 업데이트하지 않은 기기가 섞여도 기록이 사라지지 않습니다.**
  - 예전 앱은 `bates:` 키를 모르므로 무시한 채 합집합으로 다시 올립니다.
  - 새 앱은 예전 앱이 올린 접두사 없는 키를 정규화해서 받아들입니다.
- 쓰기 생략용 지문(`canon`)은 정규화한 모양으로 계산합니다. 이전 직후 색이 바뀌므로 첫 동기화에서 한 번 올라갑니다.
- 백업 파일은 v2와 v3를 모두 불러옵니다.

## 9. PWA와 오프라인

- **설치 시 캐시:** 앱 셸, 서체, `books/index.json`, `books/bates/meta.json`
- **장 캐시:** 연 장은 캐시에 남습니다. 설정에 "이 책 전체를 기기에 저장" 버튼을 둡니다 (베이츠 전체 약 3MB).
- **업데이트:** 새 서비스 워커가 기다리면 "새 버전이 있어요 · 새로고침" 토스트를 띄웁니다. 누르면 바로 바꿉니다.
- **홈 화면 안내:** 홈 화면에 추가하지 않은 사파리 탭에서는 기록이 7일 뒤 지워질 수 있다는 안내를 띄웁니다 (지금 있는 안내 유지).

## 10. 검증

1. **이전 테스트:** 실제 기록으로 `migrate()`를 돌립니다. 실제 기록은 사용자가 내보낸 백업 파일 `~/Desktop/bates-harmony-backup.json`을 씁니다 (저장소에 커밋하지 않습니다). 확인할 것:
   - 형광펜 139개가 그대로 있는지 (본문 87 + 주해 52)
   - id가 중복 없이 유일한지
   - 지운 기록과 북마크가 보존되는지
   - 색 매핑이 맞는지
2. **동기화 섞임 테스트:** v2 문서와 v3 문서를 번갈아 합쳐도 결과가 수렴하고 아무것도 사라지지 않는지 확인합니다.
3. **렌더 대조:** 모든 장의 문단 수와 주석 표지가 예전 빌드와 같은지 봅니다 (`build.py` 검증). 기존 형광펜 139개가 같은 글자 위에 다시 칠해지는지도 봅니다.
4. **아이폰 실기:**
   - 홈 화면 추가 → 비행기 모드에서 읽기
   - 형광펜·북마크
   - 아이폰↔아이패드 동기화
   - 예전 바로가기 주소
   - 업데이트 토스트

## 11. 배포와 되돌리기

- 배포 전에 사용자가 지금 앱에서 **백업 파일을 내보내 둡니다.**
- `seojae-v1`을 `main`에 합치면 같은 주소로 배포됩니다.
- 되돌리기: `main`을 이전 커밋으로 되돌리면 예전 앱이 `hb.*` 기록 그대로 열립니다. 새 앱에서 새로 칠한 형광펜은 예전 앱에 보이지 않으므로, 되돌릴 일이 생기면 백업 파일로 옮깁니다.

## 12. 이후 단계 (이번 범위 아님)

- **성경:** 새한글(허락 시), 원문 단어별(표제어 단위 한국어 뜻, STEPBible · SBLGNT · WLC), KJV
- **베이츠 재번역:** 한 장을 시범으로 번역한 뒤 방식과 모델을 정합니다. 아직 형광펜이 없는 VII장부터 진행합니다 (형광펜은 한국어 글자 위치에 묶여 있어, 이미 칠한 I–VI장을 다시 번역하면 그 형광펜이 어긋납니다).
